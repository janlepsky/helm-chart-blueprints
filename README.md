# Helm Chart Blueprints

Pre-configured Helm chart blueprints for the [mogenius](https://mogenius.com) platform. Blueprints appear as quick-start cards in the Helm install flow — selecting one auto-adds the repository and pre-fills chart name, version, namespace, release name, and default values.

## Repository Structure

```
helm-chart-blueprints/
├── index.yaml          # Blueprint list (fetched by the UI for the selector)
└── charts/
    ├── cert-manager.yaml
    ├── traefik.yaml
    └── ...
```

### `index.yaml`

A short metadata list of all available blueprints — fetched once to populate the selector UI.

### `charts/{id}.yaml`

Full blueprint definition fetched when a user selects a blueprint. Format:

```yaml
apiVersion: v1
kind: HelmBlueprint
metadata:
  id: cert-manager
  displayName: cert-manager
  description: Automated TLS certificate management for Kubernetes
  category: security
  icon: cert-manager
  tags: [tls, certificates, letsencrypt, security]
spec:
  repository:
    name: jetstack
    url: https://charts.jetstack.io
  chart:
    name: jetstack/cert-manager
    version: "v1.17.1"
  install:
    release: cert-manager
    namespace: cert-manager
  values: |
    crds:
      enabled: true
```

## Own Generic Chart (`Container` blueprint)

Most blueprints reference existing upstream charts. The **Container** blueprint is
different: it is a self-service blueprint for developers to deploy *any* container
image. It references a small generic chart maintained in this repo under
[`helm/container/`](helm/container/).

Developers only provide:

- **Image** — `image.repository` / `image.tag`
- **App name** — the Helm release name (names the Deployment, Service, Ingress, …)
- **Hostname** — `ingress.enabled` + `ingress.host` (optional)
- **HTTPS** — optional automatic TLS for the hostname via a cert-manager
  ClusterIssuer (`ingress.tls.enabled` + `ingress.tls.clusterIssuer`)

Optionally also **port**, **environment variables**, **replicas** and **resources**.
Everything else (Service, selector labels, ServiceAccount, Ingress wiring) is
generated by the chart.

## Own Generic Chart (`Crossplane Workspace` blueprints)

The **Crossplane Workspace** blueprints let developers deploy infrastructure
through Crossplane's OpenTofu/Terraform provider as a simple template. They all
reference one small generic chart in this repo under
[`helm/crossplane-workspace/`](helm/crossplane-workspace/), which renders a single
`opentofu.m.upbound.io/v1beta1` **Workspace** managed resource.

Developers only provide:

- **Source** — `workspace.source`: `Inline` (HCL in `workspace.module`) or
  `Remote` (a git module reference in `workspace.module`)
- **Variables** — `workspace.vars` (simple strings) and `workspace.varmap`
  (maps/lists)
- **Provider config** — `workspace.providerConfigRef` (which credentials/backend
  Crossplane uses)

Everything else (Workspace name from the release name, output Secret, labels,
management policies) is generated by the chart.

The first concrete blueprint is
[`workspace-azure-rg`](charts/workspace-azure-rg.yaml):
an editable template that provisions an Azure Resource Group. Add more blueprints
by pointing new `charts/*.yaml` files at the same `crossplane-workspace` chart
with different pre-filled values.

> **Cluster prerequisites:** Crossplane and the OpenTofu provider
> (`opentofu.m.upbound.io`) must be installed, and a matching
> `ClusterProviderConfig`/`ProviderConfig` (e.g. `azure`) must exist with valid
> cloud credentials. The chart only creates the Workspace, not the provider or
> its credentials.

### Hosting the charts

The charts are published as a Helm repository via **GitHub Pages** by the
[`release-chart`](.github/workflows/release-chart.yml) workflow, which runs on
pushes to `main` that touch `helm/**` and publishes to the `gh-pages` branch.

One-time setup:

1. Create an empty `gh-pages` branch.
2. Enable GitHub Pages: **Settings → Pages → Source: branch `gh-pages`, folder `/`**.

The repository is then available at
`https://janlepsky.github.io/helm-chart-blueprints`, matching the URL in
[`charts/container.yaml`](charts/container.yaml).

## Custom Blueprint Repository

Organizations can host their own private blueprint repository and configure it in the mogenius organization settings under **Helm Blueprints**. Private repos are supported via an access token.

## Contributing

To add or update a blueprint, open a PR that adds or modifies a file under `charts/` and updates `index.yaml` accordingly.
